# LetsBeParents — сайт и общий API

## Состав

- `lbp/frontend/` — публичный сайт на React, TypeScript и Vite: страницы, кабинет, Path Selector, Trust & Safety, Pricing, Find Your Path и квиз.
- `lbp/frontend/public/web-static/` — ресурсы интерфейса, пять изображений выбора пути и десять скачиваемых DOCX.
- `lbp/backend/` — общий FastAPI API с PostgreSQL, авторизацией, каталогами, сообщениями и интеграциями. В том же сервисе находятся обработчики админки.
- `admin/` — ранее опубликованный самостоятельный интерфейс админки. Для сборки сайта он не требуется; обновления этого интерфейса не входят в текущую передачу сайта.

## Зависимости и сборка сайта

Для этой версии используйте Node.js 22.22+ в ветке 22, 24.12+ в ветке 24 либо 25+ и npm. Эти требования учитывают зависимости из lockfile и зафиксированы в `engines` файла `lbp/frontend/package.json`. Версии frontend-зависимостей зафиксированы в `lbp/frontend/package-lock.json`.

1. Перейдите в `lbp/frontend/` и установите зависимости командой `npm ci`.
2. Создайте локальный `lbp/frontend/.env.production` по образцу `.env.example` либо передайте переменные защищённым окружением сборки.
3. Заполните шесть обязательных параметров Firebase Web из предоставленной конфигурации проекта `parents-698f8`. `VITE_FIREBASE_MEASUREMENT_ID` необязателен.
4. Выполните `npm run build`. Команда сначала проверяет TypeScript, затем создаёт `lbp/frontend/dist/`.

Пустые обязательные Firebase-параметры останавливают сборку. Сборка также проверяет идентификатор проекта: разрешён только `parents-698f8`. Шаблон окружения намеренно не является рабочей конфигурацией.

Сайт обращается к API относительными путями `/api/...`. Сервер, обслуживающий сайт, должен перенаправлять этот префикс к FastAPI, сохраняя cookies и заголовок Authorization. Отдельный API-домен для такого размещения не нужен.

Для прямого открытия клиентских маршрутов сервер должен возвращать `index.html`, если запрошенный путь не соответствует статическому файлу. Пути `/api/`, файлов медиа и статических ресурсов нельзя подменять HTML-страницей.

## Подготовка API

Требуется Python 3.11 или новее и совместимая PostgreSQL-база с уже подготовленной схемой приложения. Из каталога `lbp/backend/` установите зависимости командой `python -m pip install -r requirements.txt` в выделенное Python-окружение.

Шаблон `lbp/backend/.env.example` перечисляет параметры, которые реально читает сервис. Загрузку переменных в процесс обеспечивает используемый менеджер сервиса: сам `main.py` файл `.env` не читает.

Минимально необходимы:

- `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` — подключение к подготовленной PostgreSQL-базе.
- `COOKIE_ENCRYPTION_SECRET` — отдельный защищённый секрет не короче 32 символов. Его изменение не является обычной настройкой сборки и влияет на уже зашифрованные cookies.
- `PUBLIC_APP_URL` — публичный HTTPS-адрес конкретного окружения для ссылок приложения.
- Записываемые `UPLOAD_DIR` и `PRIVATE_UPLOAD_DIR`, а также корректная раздача `UPLOAD_URL_PREFIX`. Приватный каталог не должен быть доступен как публичная статика.

Команда запуска на подготовленном сервере: `python -m uvicorn main:app --host 127.0.0.1 --port 8000`. Это пример запуска процесса за reverse proxy, а не автоматическая установка сервера. TLS завершается на прокси; соединения должны корректно передавать исходную HTTPS-схему для безопасных cookies.

Сервис не создаёт полную схему базы при запуске. Дампы, история миграций и реальные данные не входят в этот репозиторий. Для нового окружения схему и доступы нужно получить отдельным защищённым способом. Одних исходников недостаточно, чтобы развернуть приложение с рабочими данными на пустой базе.

## Интеграции

- Firebase: `EXPECTED_FIREBASE_PROJECT_ID` и `FIREBASE_PROJECT_ID` должны быть `parents-698f8`; `GOOGLE_APPLICATION_CREDENTIALS` указывает на защищённый файл сервисного аккаунта на сервере. Этот файл не передаётся в Git.
- Google Vision: включайте `VISION_ENABLED` только после настройки разрешённого проекта, прав и серверной конфигурации.
- Почта: SMTP-параметры и `EMAIL_NOTIFICATIONS_ENABLED` необходимы для отправки писем подтверждения и восстановления доступа. Успешная сборка сайта не подтверждает доставку почты.
- Звонки: `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`; разрешение звонков также зависит от сохранённых настроек приложения.
- Проверка личности: параметры `DIDIT_*`; при включении необходимы реальная конфигурация провайдера и секрет проверки webhook.
- Партнёрский кабинет: `PARTNER_*`, связанные записи в базе и отдельный секрет сессий. Не полагайтесь на резервное использование административного пароля.
- Настройки `ADMIN_*` нужны только для соответствующего доступа к общему API и не требуются frontend-сборке. Административные пароли не передаются вместе с исходниками сайта.

Необязательные локальные справочники `catalog_locations.json` и `partner_services.json` исключены из Git как данные. Без них полноту справочников и партнёрских услуг следует отдельно проверить в целевом окружении.

## Данные статей и медиа

Knowledge Hub получает список и страницы статей из `/api/public/articles` и `/api/public/articles/{locale}/{slug}`. Категории, изображения, даты, просмотры и навигация строятся по API, без встроенной копии статей референса. Пагинация API учитывается при загрузке списка; карточки показываются порциями.

Сохранённые JSON-ответы, метаданные статей референса и их изображения не входят в текущую публикацию. URL медиа, возвращённые API, должны обслуживаться целевым окружением. Недостающие статьи и изображения необходимо предоставить через данные приложения, а не заменять придуманными ресурсами.

DOCX в `public/web-static/resources/` являются материалами публичного сайта, а не внутренней документацией или выгрузкой базы.

## Family Room API

Общая комната доступна двум активным, не заблокировавшим друг друга участникам активного взаимного совпадения. Каждый обращающийся участник должен иметь существующий Premium-флаг. Отдельная подписка Family Builder Pro в этой версии не проверяется. Используется обычная сессия приложения: защищённая cookie или `Authorization: Bearer`.

Все пути ниже начинаются с `/api/member/family-room`. `{profile_identifier}` — внутренний ID либо исходный UUID второго участника, не ID совпадения или плана.

| Метод и путь | Поведение |
| --- | --- |
| GET /{profile_identifier} | Возвращает matchId, plan, checklist и documents; отсутствующий план возвращается пустым без записи в базу. |
| PATCH /{profile_identifier}/plan | Частично изменяет parentingNotes, financesNotes, legalNotes. Пропущенные поля сохраняются, пустая строка очищает заметку. |
| POST /{profile_identifier}/checklist | Создаёт пункт с section: parenting, finances, legal или general и непустым label до 500 символов. |
| PATCH /checklist/{item_id} | Изменяет label и/или булево isDone; false снимает отметку. |
| DELETE /checklist/{item_id} | Удаляет пункт общей комнаты. |
| POST /{profile_identifier}/documents | Принимает multipart-поле file: JPEG, PNG, WebP или PDF, не больше MAX_UPLOAD_BYTES. |
| GET /documents/{document_id}/content | Проверяет доступ и выдаёт приватный файл как скачиваемое вложение. |
| DELETE /documents/{document_id} | Удаляет документ и файл; storageCleanupPending означает необходимость повторной серверной очистки. |

Неизвестные поля и явный null в изменяемых полях отклоняются. Максимальная длина каждого поля заметок — 20 000 символов. Ошибки: 401 — нет действующей сессии, 402 — нет Premium, 404 — объект или разрешённая пара недоступны, 413 — превышен размер файла, 415 — неподдерживаемый MIME, 422 — некорректное содержимое.

Документы используют `PRIVATE_UPLOAD_DIR/family-room/`, вне публичного `UPLOAD_DIR`. Клиенты должны скачивать `contentUrl` с сессией; публичного анонимного URL нет. Проверяются PDF-сигнатура и формат изображений, но антивирусная проверка, суммарная квота комнаты и автоматический обработчик повторной очистки не включены.

Перед запуском этой версии нужны таблицы family_plans, family_plan_checklist_items и family_plan_documents. Миграция передаётся отдельно от Git. Эти изменения добавляют серверный API, а не новые экраны сайта или мобильного приложения.

## Проверки и границы передачи

- Проверка TypeScript: `npm exec tsc -- --noEmit` из `lbp/frontend/`.
- Полная frontend-сборка: `npm run build` с конфигурацией выбранного окружения.
- После запуска API: `/api/health`, `/api/docs`, `/api/openapi.json`; без сессии `/api/auth/me` должен требовать авторизацию.
- В защищённом окружении отдельно проверяются вход по паролю и Firebase, письма, cookies, медиа, чат и звонки. Сборка не проверяет внешние сервисы.

Передаются текущие исходники, включая серверные доработки sessionToken, совместимости голосовых звонков, Ranking и Platform. Наличие изменений в Git не означает их публикацию на сервере. В частности, серверные настройки Platform не означают, что все связанные переключатели публичного интерфейса уже подключены.

Автоматические тесты, Docker-файлы, миграции, локальные артефакты, реальные настройки и пользовательские данные в этот пакет исходников не включены. Коммит в Git сам по себе не обновляет сервер.

## Хранение конфигурации

Рабочие `.env` и ключи остаются вне Git. Firebase Web-параметры с префиксом `VITE_` попадают в браузерную сборку и не являются серверным хранилищем секретов. Никогда не используйте этот префикс для паролей базы, приватного ключа Google, SMTP- или LiveKit-секретов.

Для передачи исходников GitHub Secrets не нужны. Если позже появится отдельный процесс сборки или публикации, он должен получать только необходимые ему параметры. Значения тестового и основного окружения хранятся раздельно. Существующие ключи не нужно менять только ради переноса конфигурации.
